Goals
Branch ingredient transfers

Add an Admin/Owner flow to move ingredient stock between branches.
Requirements: select source branch, destination branch, ingredient, quantity, optional note; validate stock availability; apply decrement+increment atomically (best-effort with MongoDB transactions if available, otherwise compensate safely).
Record in stock movement history (source “transfer out”, destination “transfer in”), including who did it and timestamp.
Owner dashboard: seats availability

Add a view (Owner only) showing how many seats/tables are available vs unavailable in the branches.
Define “unavailable” as tables with IsOrderingOpen == true (occupied) from TableOrderingSessionService / TableRegistryService.
Display totals and per-table status; optionally filter by branch if your tables are branch-scoped.
Supplies (inventory) cost column

Add Cost fields to supplies/ingredients:
CostPerUnit (decimal) and a clear Unit (e.g., ml, g, pcs) OR CostPerMl for liquids.
Update Admin inventory CRUD + list to show and edit cost.
Backfill existing items with default cost = 0 (so nothing breaks).
Sauce container + usage math

Model sauces as 2 liters (2000 ml) per container.
When an order consumes sauce:
Per 1 chicken: consume 4 ml (tolerance ±1 ml is informational; implement as 4 ml default).
Example: 4 wings → 16 ml.
Implement stock deduction using ml-based units for sauce items when kitchen marks order “Completed” (or wherever stock is decremented today).
Ensure recipes / menu-to-ingredient mapping supports ml quantities.
Supplies expiration column

Add ExpirationDate (DateTime?) and/or ExpirationDays + ReceivedAt rules (pick one consistent approach).
Update inventory list/UI to display expiration and highlight expired/near-expiry (e.g., <= 7 days).
Add filtering/sorting for expired items.
Profit / loss analytics

Compute COGS per order from ingredient usage (recipe lines + sauce ml rules + quantities).
Add to revenue analytics:
OrderCost (COGS)
Profit = OrderTotal - OrderCost
Roll up overall profit/loss in Admin dashboard and Sales pages (daily totals and per-branch for owner).
Store computed cost/profit on the order record at completion time to avoid recomputing historically (recommended), but allow recompute if costs change (optional).
Deliverables
Updated models (ingredients/inventory/order fields as needed)
Updated services for stock movement, transfers, and costing
Updated admin/kitchen UI pages
Any MongoDB collection/index updates and safe defaults for existing data
Basic test plan: manual steps to verify transfer, seat counts, costing/profit
Constraints
Keep authorization consistent: Owner-only for global views and transfers across branches; branch managers limited to their branch.
Do not break existing kiosk/QR/kitchen flows.
Follow existing repository patterns (MongoDB access via services, MVC areas, antiforgery, etc.).
